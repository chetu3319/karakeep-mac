# Study (AI rework) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the page-scoped "AI Co-Pilot" drawer and the floating selection HUDs with two things:
- **Study**, a whole-document panel with attachments, clickable references and persisted chats;
- inline answers inside the existing selection toolbar.

**Architecture:**
- **Pure logic** is unit-tested with vitest:
  - reference parsing, document assembly and the chat file format, in `src/shared` and `src/renderer/src/lib`;
  - quote matching, which is shared by both readers.
- **Main process:** owns Gemini (adding a `study` mode with image parts), local chat storage, and Karakeep sync. Sync uploads an HTML file and attaches it to the bookmark as `userUploaded`.
- **Renderer:** owns document text extraction, the Study panel, and jumping to references.
- **Web reader preload:** owns the in-page toolbar, reveal-quote and region capture, using DOM APIs only (no `innerHTML`).

**Tech Stack:** Electron 32, electron-vite, React 18, TypeScript strict, Tailwind, @embedpdf, Gemini REST over `net.fetch`, vitest (new, dev only).

**Spec:** `docs/superpowers/specs/2026-10-12-study-ai-design.md`. Read it before any task; it holds the UI description and every settled call.

## Global Constraints

- `npm run typecheck` and `npx vitest run` pass after every task.
- No emoji in UI copy. Use line icons from `src/renderer/src/components/Icon.tsx`, the emerald accent, and neutral surfaces. The in-page web UI uses the `.kh-pop` styles from `src/shared/highlightUi.ts`.
- `src/preload/webpane.ts` runs inside untrusted pages. It must never use `innerHTML` (or similar) with model or page text; use `textContent` and `createElement` only.
- The Gemini key stays in main. Karakeep calls go through `src/main/api.ts` and use `net.fetch`.
- Study's document budget is `STUDY_BUDGET_CHARS = 400_000`. If a request is too large, retry once at half the budget.
- Study files are named exactly `karakeep-desktop-study.html`, and `STUDY_SCHEMA_VERSION = 1`.
- **Reference marker grammar:**
  - `[[ref p=4 "quote"]]`, `[[ref fig p=4 "quote"]]`, or `[[ref "quote"]]` (no page, for web content).
  - Quotes are at most 25 words.
- Inline answers are at most 3 sentences, with thinking level `low`. Study uses thinking level `medium`.
- The keyboard shortcut is ⌥⌘S (View → Study panel).
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A long PDF (300+ pages, more than 400k characters)** must trim to the budget, keeping the first two pages, the last page, the current page and the focus pages (±1). Extraction must show progress and must not freeze the UI. Tested in Task 1 (`assembleDocument` trims long docs).
2. **A quote broken by PDF layout** must still match. That covers a hyphen at a line break (`atten-\ntion`), the ﬁ/ﬂ ligatures, curly versus straight quotes, and differences in case or whitespace. Tested in Task 1 (`findQuote` cases).
3. **Model text containing `<script>`, `</script>` or `&`** must come out escaped in the transcript HTML. It must not break the JSON block or run when the file is opened in Karakeep's web app. Tested in Task 1 (studyFile escaping).
4. **Malformed or unclosed reference markers**, including ones that are mid-stream, must never show raw `[[ref` text or throw. Tested in Task 1 (`parseRefs` streaming and malformed cases).
5. **Karakeep unreachable during a save:** the chat is still saved locally, the status shows failed, and a later save or retry pushes it. The old remote file is only detached after the new one is attached. Tested in Task 3 (studySync failure cases).
